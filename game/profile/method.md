# 制作方法

来源：`game/journal/` 日志，按线索跨日期蒸馏。业务状态与待定决策不进本文件。

## 先试玩法，后治理代码

一开始我不纠结代码质量，等明显卡壳了再去治理它；关键在于先让玩法（或产品机制）试出来。玩法比真实产品好试，不需要很多现实条件，能玩就行。为了保持可控，我倾向把东西压缩在单个代码文件、少量文档里，不断压缩让代码更有条理、更有结构——但前提始终是先有玩法。

## 多模型交叉评审，按长处分工

重要改动我会拿多个模型交叉评审，按各自的长处分工：最稳的负责整合，读代码强的负责找核心点，会漂移的只用来打开方向、不用来收敛。哪个模型截断了或漂移了就换下一个，不硬用；生成与找核心点可以由不同模型接力完成。

## 手机产生、电脑整合的接力循环

我的创作流是：在手机上用语音产生想法，一个一个成形；到电脑上整合；发现空心的地方回手机接着补；补清楚再回来整理，如此循环。以手机为中心、手机和电脑接力非常关键——语音输入让想法更详细、更真实、更原始，输入质量直接决定想法质量。
