# 日志到意图

把 `<集>/journal/` 中的混合日志提取为**同一集** `<集>/intention/` 下的人类意图记录。intention 是对齐层：记录**人类到底想要什么**，用以对齐人机协作的信息。典型来源有两类：

1. **AI 问人类的时候**：AI 提问后人类给出的回答与澄清（包括"这个问题问得好，让我想清了意图"这类反照）。
2. **人机小交互出现摩擦时**：AI 做偏了、理解偏差、被当成纯执行者等摩擦现场，人类主动澄清"我要的是 X，不是 Y"。

意图不只关于协作方式本身——关于业务、平台、创作的意图澄清同样入本层，**按主题分文件，主题集与同集 insight / roadmap 对齐**（`default/` 为 `ai.md`、`business.md`、`creative.md`、`platform.md`）。

## 层间分工

| 问题 | 去向 |
|------|------|
| 这是"我到底想要什么（要 X 不要 Y）"？ | `<集>/intention/` |
| 这是"我是什么样的人 / 我反复怎么判断"？ | `<集>/profile/` |
| 这是"我想通了什么机制"？ | `<集>/insight/` |
| 这是"我要做什么 / 选什么"？ | `<集>/roadmap/` |
| 这是"发生了什么"？ | 留在 `<集>/journal/` |

**判据**：意图必须明确表达人类想要什么——"要 X，不要 Y""先问再做""交给谁、按什么来"——能据此对齐后续协作。感悟、事件、无落点的感叹不收；拿不准就不收。

**与 insight / roadmap 的分界**：同一事件在各层写法不同——insight 写成可对错的命题，roadmap 写成决策或状态，本层写成给 AI 的指令式意图；已成为决策且指令不新增信息的，本层不重复收录（以 roadmap 为准）。

## 原则

- **单位是意图线索，不是日期文件**，多对多。
- **以最新为准**：人机协作的澄清会翻转，跨日合并、就地改写，被推翻的直接替换。
- **写给 AI 读**：祈使或明确陈述，去掉叙事铺垫，一条意图 + 一句背景。
- **与 profile 分工不复制**：价值观式的稳定判断归 `<集>/profile/`；澄清沉淀为稳定特征后，本层改写为互链。
- 目前仅 `default/` 启用本层；`write/` 集暂不设 `intention/`。

## 流程

1. **扫描**：通读本记忆集的全部日志——`<集>/journal/` 全部，加上集根的当天日志（如 `default/2026-09-26.md`），按意图类关键词定位候选：要、不要、别、希望、应该、必须、交给、按、先、只、统一、分流、澄清、不对、不是这个、执行者、掌控、验收、约束。不读其他记忆集的日志。
2. **过滤**：按判据过滤，能对齐协作的才收；与 roadmap 决策重复的不收。
3. **聚类**：同一意图跨日期合并为一条，按主题归入与 insight / roadmap 对应的主题文件；被后续澄清推翻的就地改写。
4. **合并**：读现有 `<集>/intention/` 文件与同集 insight / roadmap 防重复，新线索增条目，已有条目改写，过时的移除。

## 输出

`<集>/intention/` 按主题分文件，主题集与同集 insight / roadmap 对齐（`default/`：`ai.md`、`business.md`、`creative.md`、`platform.md`，主题名延续各层命名法，不用日期）；日志里没有内容的主题不建文件。条目一行一条：

```markdown
# 主题名

- **意图**：要 X，不要 Y。背景：摩擦或提问一句（YYYY-MM-DD）。
```

## 自查

增改条目后逐项过一遍，任一项不过就改到过：

| 标准 | 要求 | 反例 |
|------|------|------|
| 忠实度 | 指令在日志里有直接依据；推断出的补救措施降格措辞（「鼓励」「优先」）或标注为推断 | 日志只说「提问有帮助」，条目写成「动手前必须先提问」 |
| 约束完整 | 压缩时保留改变含义的关键约束（范围、数量、例外） | 「我等不了一个人」压成「给别人成长时间」 |
| 张力标注 | 跨条目看似矛盾的意图写清解耦条件 | 「带人须有收益」与「规模化培养」并列不注条件 |
| 跨层去重 | 与同集 insight/roadmap 实质重复的不收；保留的条目须与所在层写法有别并互链 | 决策已入 roadmap，意图条目复述决策 |
| 格式与分类 | 主题文件与同集 insight/roadmap 对齐，条目一行、`**意图**` + 背景 + 日期 | 新建未对齐主题的文件名 |
| 覆盖度 | 强意图候选不留在日志里；排除的条目能在其他层找到归宿 | 明确的「要 X 不要 Y」只存在于日志 |

## 边界

- 不收事件经过（留 `<集>/journal/`）、稳定特征（归 `<集>/profile/`）、机制命题（归 `<集>/insight/`）、决策与目标（归 `<集>/roadmap/`）。
- 日志里没有的意图不编造；拿不准就不收。
- intention 是给 AI 读的对齐信息，不是建议，也不是对用户的输出。
