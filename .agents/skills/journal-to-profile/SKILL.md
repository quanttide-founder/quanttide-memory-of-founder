# 日志到档案

把 `<集>/journal/` 中的混合日志蒸馏为**同一集** `<集>/profile/` 下的个人档案。每份档案是一条独立的轴，共享同一套提炼方法。档案轴的文件名因记忆集而异：`default/` 为五轴（下表），`write/` 为创作动机 / 创作方法 / 创作困境。

## 档案轴

| 文件 | 轴 | 收什么 |
|------|-----|--------|
| `<集>/profile/emotions.md` | 情绪 | 状态与波动：恐惧、喘息、掌控、失控、厌倦、疏离、信心 |
| `<集>/profile/values.md` | 价值观 | 不可妥协的判断线：什么值得做、什么不做、以什么为准 |
| `<集>/profile/triggers.md` | 触发点 | 让状态掉下去的诱因及其反应模式（因），与 emotions 的结果（果）互为呼应 |
| `<集>/profile/methods.md` | 方法论 | 反复使用的思维框架（怎么看问题）与应对策略（卡住时怎么爬出来） |
| `<集>/profile/expressions.md` | 表达 | 叙事指纹：写作习惯、重复的结构与口吻、母题偏好 |

## 原则

- **单位是线索，不是日期文件**。一条线索可跨多篇日志，一篇日志可贡献多条线索，多对多。
- **只收跨时间稳定的特征**。单次事件、具体项目状态、待定决策不进档案——决策归 `<集>/roadmap/`，实现状态归 `report/`。
- **体裁是第一人称的你自己**，对照 `../fiction/观察站/1_情绪日记/` 的口吻。不加来源标注、日期标注。
- **一稿多投允许但不重复**：同一条日志可同时贡献给多轴（如"熟练即厌倦"既是 trigger 也是 method 的反面），但每个文件里只写该轴的侧面，不整段复制。

## 流程

1. **扫描**：通读本记忆集 `<集>/journal/` 下全部日志，忽略日期，按五轴各自的关键词扫描。不读其他记忆集的日志。
2. **聚类**：同一线索跨日期合并为一条。判断依据是本质相同，而非措辞相似。
3. **蒸馏**：剥离具体项目名、工具名、业务细节，留下特征本身。允许保留一两句引发它的事件作背景，不展开论述。
4. **合并**：读现有档案文件，新线索新增小节，已有线索就地更新（改写而非追加），重复的删掉。

## 各轴要领

- **emotions**：第一人称情绪散文，2-4 段，小节标题为四到六字情绪主题。深层线索（长期恐惧、核心冲突）只出现一次也单独成节。情绪反转（失败主义→恢复）不拆两条，同节呈现两面。
- **values**：写成"我如何判断"而非"世界应该怎样"。每条值包含：判断线本身 + 它排除了什么。优先取有行为证据的（实际拒绝过、坚持过什么），而非口号。
- **triggers**：写成"诱因 → 反应"对。反应包括情绪、行为、身体三个层面的信号。与 emotions 分工：triggers 记"什么触发"，emotions 记"触发后是什么感受"，交叉引用不重复。习惯性对策不写这里（归 methods）。
- **methods**：分两栏——思维框架（分析问题时反复套用的模型，如"缩小窗口""从实验室到平台"）与应对策略（卡住时的实际解法，如"写不出来就找合规来套"）。每条写清适用条件，防止被误用到不匹配的场景。
- **expressions**：只收创作行为特征，不收观点本身（观点归 values/methods）。写成"我惯常怎么写"：重复出现的结构、男女主设定倾向、母题偏好、同构倾向。来自日志中谈写作、改稿、与 AI 协作写书的段落；观察站素材与成稿也可作旁证，但标注为推断而非日志证据。

## 输出

各文件结构统一：

```markdown
# 档案名

来源：`<集>/journal/` 日志，按线索跨日期蒸馏。业务状态与待定决策不进本文件。

## 线索主题名

第一人称，2-4 段（或按该轴要领的短结构）。
```

## 边界

- 日志里没有的轴，该文件保持只有头部，不编造。
- 情绪反转、认知升级：改写原条目，不追加新条目。
- 档案只描述特征，不给建议（建议是对用户的输出，不是档案内容）。
