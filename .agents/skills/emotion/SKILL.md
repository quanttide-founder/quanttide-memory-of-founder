# 情绪提炼

把 `journal/` 中的混合日志提炼为 `profile/emotions.md` 中的情绪档案。

## 原则

- **单位是情绪线索，不是日期文件**。一条线索可跨多篇日志，一篇日志可贡献多条线索，多对多。
- **只收情绪，不收业务**。业务判断、工程观察、组织策略一律不进 emotions.md。
- **体裁是第一人称情绪记录**。不加来源标注、日期标注、结构化列表（表格/编号列表）。

## 流程

1. **扫描**：通读目标日志（默认 `journal/default/` 全部 + `journal/` 根目录的最新篇），忽略日期，按情绪关键词扫描：恐惧、失败感、掌控、失控、疲惫、喘息、厌倦、疏离、焦虑、信心、平静……
2. **聚类**：同一情绪跨日期合并为一条线索。判断依据是情绪本质相同，而非措辞相似。
3. **纯化**：把线索写成第一人称、无结构的情绪散文，体裁对照 `../fiction/草稿箱/2_情绪日记/`。剥离具体项目名、工具名、业务细节——留下情绪本身。允许保留引发情绪的具体事件作为一两句背景，但不展开论述。
4. **分流**：业务/工程洞察跳过，不产出。
5. **合并**：读现有 `profile/emotions.md`，新线索新增小节，已有线索就地更新（改写而非追加），重复的删掉。小节标题为四到六个字的情绪主题。

## 输出

写入 `profile/emotions.md`，结构：

```markdown
# 情绪档案

按情绪线索跨日期聚类提炼。

## 情绪主题名

第一人称情绪散文，2-4 段。
```

## 边界

- 深层线索（长期恐惧、核心冲突）单独成节，即使只出现过一次，如「不敢一个人面对」这类。
- 情绪发生反转时（如从失败主义到恢复信心），在同一小节内呈现两面，不拆成两条。
