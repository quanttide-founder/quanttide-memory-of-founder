# 日志到路线图

把 `<集>/journal/` 中的混合日志蒸馏为**同一集** `<集>/roadmap/` 下的主题路线图。roadmap 是方向层，章节顺序即推理顺序：目标（元目标是目标的子层）→ 核心问题（卡在目标与决策之间）→ 决策（对问题的回应）。

## 三问过滤

| 问题 | 去向 |
|------|------|
| 这是"要做什么 / 选什么 / 在问什么"？ | `<集>/roadmap/` |
| 这是"发生了什么"？ | 留在 `<集>/journal/` |
| 这是"我是什么样的人"？ | `<集>/profile/` |

三问都答不上的（单次一闪念、无行动、无后续）不收。

## 证据分级

- 多日重复或已有行动 = **已决策**
- 单次提及、无行动 = **待决策候选**
- 反复出现且未解 = **核心问题**
- 日志中标注的长期主题 = **元目标**（写作时归入「目标」节的 `### 元目标` 子层，不设顶级节）

## 原则

- **单位是决策线索，不是日期文件**，多对多。
- **以最新状态为准**：决策会翻转（想过后决定"不动"），跨日合并、就地改写；演变史是 journal 的职责，roadmap 只反映当前状态。
- **与 profile 分工不复制**：profile 收"怎么判断"（价值观、思维框架），roadmap 收"判断出了什么"（选择、目标）。同一内容两处出现时写法必须不同，或一方只留互链。
- **不收**：事件、情绪、业务状态、应对策略——分别留在 journal 或归 profile。

## 流程

1. **扫描**：通读本记忆集的全部日志——`<集>/journal/` 全部，加上集根的当天日志（如 `default/2026-09-26.md`），按方向类关键词定位候选：决定、决定不、先做、优先、不动、交给、合并、拆开、待定、需要考虑、还没定、怎么找、问题是、主题：。不读其他记忆集的日志。
2. **过滤**：三问过滤 + 证据分级，拿不准的降级处理（已决策 → 待决策）。
3. **聚类**：同一决策/问题跨日期合并为一条，按主题归入路线图文件。
4. **合并**：读现有 `<集>/roadmap/` 文件，新线索增条目，已有条目按最新状态改写，被翻转的决策直接替换，过时的移除。

## 输出

`<集>/roadmap/` 按主题分文件（`default/` 如 `business.md`、`platform.md`，`write/` 如 `职场言情.md`、`重生言情.md`），命名延续主题命名法，不用日期。文件内章节按序出现，空节省略：

```markdown
# 主题名

## 目标
### 元目标
## 核心问题
## 已决策
## 待决策
```

条目一行一条，祈使句或陈述句，必要时括注依据或约束。

## 边界

- **已决策必须有行动佐证**，或日志中有明确的"决定不动"记录；拿不准就降级为待决策。
- **待决策要写清卡在哪**：缺什么信息、等什么条件、还在考虑什么。
- 元目标跨主题时不重复收录，放最贴切的一个主题文件。
- roadmap 不记录决策是怎么来的，只记录决策是什么。
