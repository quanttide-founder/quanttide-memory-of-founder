# 日志到洞察

把 `<集>/journal/` 中的混合日志蒸馏为**同一集** `<集>/insight/` 下的认知洞察。insight 是认知层：收"我想通了什么"——关于机制、规律、因果、临界点的命题。它不是"我是什么样的人"（`<集>/profile/`），也不是"我要做什么"（`<集>/roadmap/`）。

## 三问过滤

| 问题 | 去向 |
|------|------|
| 这是"我想通了：X 其实是因为 Y"？ | `<集>/insight/` |
| 这是"我是什么样的人 / 我反复怎么判断"？ | `<集>/profile/` |
| 这是"我要做什么 / 选什么"？ | `<集>/roadmap/` |
| 这是"发生了什么"？ | 留在 `<集>/journal/` |

**命题判据**：洞察必须是可对错判断的命题（"X 导致 Y""Z 条件下 W 更优"）。感受、愿望、事件经过、无落点的感叹都不收；拿不准就不收。

## 证据分级

- 多日重复或有验证 / 应用行动 = **已确认**
- 单次想通、未验证 = **假说**
- 被后续日志推翻 = 就地改写或移除，以最新为准

## 原则

- **单位是认识线索，不是日期文件**，多对多。
- **分工不复制**：命题已在他层完整收录时（如 `<集>/profile/` 的方法论文件已有同一机制的框架化写法），本层只写不同侧面或留互链。journal 保留发现过程的叙事，insight 只留结论加一句依据。
- **晋升与降级**：命题反复套用、稳定为思维框架后，并入 `<集>/profile/` 的方法论文件（本处改写为互链）；命题引出选择后，选择归 `<集>/roadmap/`，本处只留命题。
- **只陈述认识，不给建议**，也不写"所以要做什么"（归 `roadmap/`）。

## 流程

1. **扫描**：通读本记忆集的全部日志——`<集>/journal/` 全部，加上集根的当天日志（如 `default/2026-09-26.md`），按认知类关键词定位：发现、意识到、原来、其实、关键是、临界点、原因在于、实际上、这样就会、规律、核心点。不读其他记忆集的日志。
2. **过滤**：三问过滤 + 命题判据；拿不准降级为假说或不收。
3. **聚类**：同一认识跨日期合并为一条，按主题归入 insight 文件。
4. **合并**：读现有 `<集>/insight/` 与可能重叠的 `<集>/profile/`、`<集>/roadmap/` 条目——新线索增条目，已有条目就地改写，被推翻的移除，重复的留互链。

## 输出

`<集>/insight/` 按主题分文件（`default/` 如 `business.md`、`ai.md`，`write/` 如 `高跟鞋.md`），命名延续主题命名法，不用日期。文件内分两节，空节省略：

```markdown
# 主题名

## 已确认

- **命题**：机制一句话。依据：事件简述（日期）。

## 假说

- **命题**：机制一句话。依据：事件简述（日期）。
```

命题用陈述句（"X 导致 Y"），不写"我觉得可能"；依据一句带日期，不展开叙事。

## 边界

- 不收感受与情绪（归 `<集>/profile/` 的情绪文件）、决策与待办（归 `<集>/roadmap/`）、事件经过（留 `<集>/journal/`）。
- 已确认必须有测试或行动佐证；拿不准一律降级为假说。
- 同一命题不在两处完整展开；跨层只留互链。
