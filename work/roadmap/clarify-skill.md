好，先做显性化层。下面是能直接落成 SKILL.md 的第一版设计。

一、边界先定死

这个 skill 只干一件事：把「不对劲」翻译成一段能粘回对话的提示词。它不做停靠（用户自己召唤）、不做情绪检测、第一版也不接 MCP——规则先用本地文件记，验证「规则从偏差中长出来」这个假设成不成立。

二、触发

显式召唤/pause

不猜意图，不自动触发。用户没召唤就什么都不做。

三、流程：三步，最多四问

第 1 步 · 命名状态（一问，可跳过）

先不解决问题。你现在是：急 / 失控 / 烦 / 说不清？

只求一个词。作用是拉开距离，不是分析。用户说「跳过」就直接进第 2 步。

第 2 步 · 定位上下文差（两问）

① 你原本以为它知道/会做什么？
② 它实际做了什么？

两问必须落到具体行为，不接受「它就是不行」这类概括——概括是情绪，不是信息。如果用户答得笼统，追问一次：「举它刚才那句话或那个动作」。

第 3 步 · 生成提示词（产出）

把 ①② 的差，写成一段可直接粘回对话的话。模板：

```
刚才你的回答偏在【实际行为】，我需要的是【原本预期】。
差异在于【上下文差】。
接下来请【具体修正指令】。
```

同时做两件附带的事：

· 查旧规则：读 rules.md，有同类偏差就浮出来——「上次类似情况你总结过：……，要不要直接用？」
· 追加记录：把这次的差写进 deviations.md（时间、场景、差、生成的提示词）。

四、规则怎么长出来

第一版不自动提炼规则，只做候选标记。当 deviations.md 里同一类差出现第 2 次，skill 在输出末尾提一句：

这类差是第 2 次出现了。要不要把它写成一条规则？〔是〕→ 追加进 rules.md

规则由用户点头才落库。这样「长出来」是真实的，不是我替你预设的。

五、一次完整走查

用户：「/停一下，它又在给我写一大堆。」
→ 命名：烦
→ ① 我以为它知道我要的是能直接用的短结论 ② 它给了五段铺陈
→ 输出：

刚才你的回答偏在铺陈展开，我需要的是能直接用的短结论。差异在于我默认了「结论优先、细节按需」，你按「全面覆盖」来写。接下来请先给三行以内的结论，细节我追问再展开。

→ 查规则：无 → 记入 deviations.md

第二次同类出现时，skill 浮出候选规则：「先结论后细节，除非我明确要展开」。

六、要验证的三个假设

1. 三问会不会太重 → 看用户在第 1 步跳过的比例；
2. 生成的提示词用户会不会真的粘回去 → 这是核心指标，不粘就等于没翻译成功；
3. 规则候选浮出时用户点头率 → 低了说明提炼粒度不对。

先跑两周，再决定要不要往 MCP 上搬。搬的时候，deviations.md 和 rules.md 原样迁成 server 的状态，skill 只留流程——这个分层现在就该守住。
