# 方法论

来源：`journal/` 日志，按线索跨日期蒸馏。业务状态与待定决策不进本文件。

## 思维框架

### 产生一个想法就分流

每冒出一个想法立刻归位，不攒着。手动的加工量会变大，但注意力不淤积，思路保持清爽。适用条件：想法产生速度超过单次处理能力时。

### 先说出/写出来

想法说不出来之前心里阻塞，说出来就流动了。适用条件：任何模糊、卡住的时刻；不适用于需要先想清楚才能说的场合。

### 从上下文差异找规则

AI 用得不顺手、或者输出不对劲时，先问"我和它的上下文差在哪"，把差异显性化说给它——规则就是这样一条条长出来的。适用条件：多次出现同一类偏差时。

### 采样胜过穷尽

日志这类无穷无尽、极易产生的东西不怕丢，采样一段时间自然会稳固出结构。适用条件：面对高频、易再生的素材时——重点从"记全"转向"提炼值和产生结构"。

### 先备数据，再写小应用现场处理

把数据准备好，写个小程序上去，遇到想说的现场处理即可；这样能快速得到一个可验证的新结构。适用条件：需要快速验证一个想法时。

### 分权制衡

手机上做一组 reviewer 与电脑上的 owner 制衡；要求他们的输出"新实习生能看懂"，借此摸清表达毛病并纠正。适用条件：需要同时保质量与保产出的维护场景。

## 应对策略

- **卡住 → 先放下**：承认现状（"对 PI 记忆的智力只能到这个程度"），治理需要时间。
- **混乱 → 定关键下一步**：从"该建私有主数据了"这类判断切入。
- **夜里孤独 → 承认它是转型期常态**：无异于重新创业，支持弱是正常的。
- **AI 不顺手 → 找上下文差异并显性化**：规则长出来之后，人机协作的边界就清楚了。
