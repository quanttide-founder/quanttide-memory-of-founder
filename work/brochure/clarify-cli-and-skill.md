先分清「介绍给谁」，再决定怎么说

你的目标用户不是一个整体，至少两层，话术完全不同：

核心层：已经在 agentic 环境里重度协作的人（Claude Code、Cursor、终端里跑 AI 的开发者/独立开发者）。他们天天遇到「不对劲」，但把它当成常态忍了。这层人听得懂「上下文差」，也接受 CLI。

外围层：用 AI 干活、但开始在意协作质量的知识工作者。他们说不清问题在哪，只会说「AI 有时候就是不行」。这层人需要场景，不需要概念。

对核心层可以讲结构，对外围层只能讲场景。下面的话术按层分开。

一句话核心叙事（对外围层也能听懂）

你和 AI 之间差的，往往不是 AI 不够强，是你以为它知道、它其实不知道。这个工具帮你把这个「差」说清楚，并且记住——下次不用再说一遍。

这句话有三个作用：把责任从 AI 挪回「差」、给出动作（说清楚）、给出长期价值（记住）。不要说「意图澄清」这四个字，用户听不懂，会以为是哲学工具。

电梯版（30 秒，对核心层）

你在终端里用 AI 写代码，是不是经常它给了一大堆，你心里「不对」，但又懒得重写 prompt，就凑合着改？这个工具就是给那个「不对」的瞬间用的：一条命令，把「我以为它知道什么 / 它实际做了什么 / 差在哪」记下来，生成一句能直接粘回去的话。用几次，它会发现你反复需要澄清的是同一件事，问你要不要立成规则。规则是你的，换哪个 AI 客户端都带着走。

关键词：那个「不对」的瞬间。核心层一听就懂，因为他们每天都在忍这个瞬间。

场景版（对外围层，讲三个时刻）

开始干活前，它让你先写三行：我要什么、我假设它知道什么、什么算干成了。这三行写完，很多返工就不会发生。

干到一半觉得不对劲，一条命令，记下「哪里偏了」，它给你一句能粘回去的话，把方向拉回来。

干完了，它把你这一路的修订摊开：你反复需要澄清的，是不是同一件事？是的话，沉淀成一条规则，下次开新任务自动带上。

三个时刻对应 declare / revise / close，但用户听到的是三个动作，不是一个数据结构。

对比版（回答「这跟 X 有什么区别」）

这是必答题，提前准备好：

跟 ChatGPT memory 的区别：memory 是 AI 记你，黑箱，绑在它家模型上。这个是你记你自己，白箱，每条你都看得见、点过头，换个客户端照样带着走。

跟 prompt 模板库的区别：模板库是别人总结的通用规则。你沉淀的是你自己反复踩的坑，粒度天然贴合你。

跟我直接改 prompt 的区别：改 prompt 你留下的是「改成什么」，这个留下的是「为什么改」——沉淀的是判断，不是文本。

三个对比都要一句话打完，不要展开，展开就变成辩论。

三个要避免的说法

1. 别用「意图」「上下文差」「显性化」当卖点词。这些是你内部的语言，用来设计可以，用来介绍会把人挡在门外。对外只说「你以为它知道的」和「它实际知道的」。
2. 别把它包装成「正念工具」。正念是你设计里的机制，不是卖点。对开发者说正念，会显得不专业；对知识工作者说，会显得玄。机制留在产品里，别放到介绍里。
3. 别说「提升协作效率」。这句话谁都在说，等于没说。你的真实承诺是减少「不对劲但忍了」的次数，具体、可感、可验证。

一个必须诚实说的前提

这个工具要求用户多一步——主动召唤、主动写几行。主流产品都在消灭这一步，你在要求用户付出这一步。所以介绍时不要回避，反而要把它变成筛选器：

这个工具不自动、不无感。它要求你在觉得不对劲时停一下，写几行。如果你愿意为「和 AI 少差一点」付出这个动作，它值得；如果你想全自动，它不适合你。

主动劝退，比硬拉人进来更有说服力——因为你的目标用户恰恰是「愿意为协作质量多花一步」的那群人。这句话本身就是筛选器。

最后一个验证性问题

介绍完之后，问对方一句：

你上次觉得 AI「不对劲」但忍了，是什么时候？

他能立刻举出一个具体例子，就是目标用户；他要想半天，就不是。这句话比任何介绍词都更能告诉你，你的用户在哪。
