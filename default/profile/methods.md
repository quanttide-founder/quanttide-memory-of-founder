# 方法论

来源：`journal/` 日志，按线索跨日期蒸馏。业务状态与待定决策不进本文件。

## 思维框架

### 缩小窗口

范围失控时主动收缩注意力。大幅缩小窗口、围绕业务之后，事情反而清晰。适用条件：注意力已经超载；不适用于还没充分展开的早期探索。

### 非商业化与商业化切开

用非商业化的部分（社区）承载大量失败，公司只专注其中商业化的一小部分。因为业务边界决定吃不完社区的商业价值，把它作为权利开放给盟友。适用条件：生态内存在大量试错活动时。

### 从实验室到平台

生产环境是平台，实验阶段是实验室。先把东西放进实验室（允许失败），活下来的再搬上平台。实训基地是实验室，公司是平台。适用条件：评估吸收外部产出时。

### 量潮经济体视角

把量潮作为独立经济体来描述，制度和标准化体系是地基和框架。市场交易看成两个经济体之间的交易，思路就会被拉到熟悉的范围内。适用条件：分析任何对外商业关系时。

### 从依赖个人到依赖规则

创始人一对一额外投入应当越来越少，转向基于规则、去中心化的方式。杠杆率来自成熟度：AI 教人是一层，实训基地又是一层。适用条件：判断某件事该不该自己做时。

### 客户视角重组

职能分解方便内部协作，但客户看到的是按顺序的项目阶段。把职能式工作档案改成与业务对齐、按客户理解的视角重组。适用条件：内部文档与客户体验脱节时。

## 应对策略

- **千头万绪 → 装进框架**：不逐条处理，先建一个容器把它们装起来。
- **沮丧 → 回到虚构世界**：从现实切回创作，重新理解做这件事的意义。
- **写不出来 → 找合规来套**：把刚性约束当脚手架，套上政策反而推得动。
- **找不到方向 → 去建设平台**：网站、平台是肯定要做的事；做不下去时，再看怎么把平台用到现实。
- **复杂度失控 → 用现有项目做阶梯**：引入已有项目进工作流，先把系统复杂度降下来，避免观测系统本身又造一个系统。
- **高压 → 补觉与放手**：睡一觉充电回来；更多让团队成员做，学会放手。
- **传播纠结 → 交给标准化**：怎么发都传播不出去的，不纠结，交给团队流程。
