# 氛围编程方法论

## 你做的事情的本质

你主动卸掉十年编程经验，模拟一个普通人的认知负荷，去探索一套”只要遵循一些习惯就能做到“的AI协作流程。你不是在教人写代码，而是在用专业判断力做减法——把外围复杂度封装掉，只露出普通人能承受的界面。

## 核心方法：一个关键习惯

整套工作流里最关键的那个动作是：当AI输出不对时，先让它解释”你为什么这样写“，找到原因，再基于原因重新许愿。

这一步把”读代码改代码“的专业调试行为，转化成了”追问原因→用自然语言描述问题→重新提问“的对话行为。门槛从”需要懂编程“降到了”需要会提问“。

## 为什么它依赖”感觉“

这个”追问→观察→再追问“的循环，没法模板化。因为：

• 有两层反思同时在发生：AI在解释自己的逻辑，你在观察它的思考质量并校准自己的判断力

• 提问的深度取决于你能否感知到”哪里不对劲“——这个直觉是模糊的、肉身的，只能在一次次具体折腾中长出来

• 一旦模板化，人就变成了对着模板填空，那个”感觉“就死了

所以你封装了外围的复杂度，但刻意没有封装核心——你保留了一个需要人自己去生长的空间。

## 传播的出路

方法太依赖感觉，所以传播的关键不是”怎么让更多人学会“，而是”怎么让更多人有机会经历类似的过程“：

• 不传知识，传体验。 创造低门槛场景，让人坐下来面对AI和一个具体目标开始折腾，你在旁边观察、偶尔点拨。

• 不写教程，写思考过程。 展示”我怎么从一串串想到一个游戏、怎么跟AI死磕、怎么提炼出方法论“的完整轨迹，读者会自己代入和吸收。

• 找真实场景切入。 找店主朋友、做活动的朋友，带着”帮你解决个具体问题“的姿态去跑你的工作流。对方没有学习压力，你也能在真实互动中观察那个”感觉“是怎么在别人身上冒出来的。

• 接受火种逻辑。 不是所有人都能长出来，找到那些有”折腾潜质“的人就够了。


## 小结

你在做的事情，是用十年经验设计一条普通人能走的路，但这条路的最后一段必须靠每个人自己走——你要做的不是把那段路也铺好，而是让更多人愿意上路，并且在路上有人陪着走几步。
